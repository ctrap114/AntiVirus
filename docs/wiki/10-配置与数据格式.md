# 10. 配置与数据格式

本章汇总 Everbloom Security 的全部外部配置面与数据文件格式。

---

## 10.1 配置面总览

| 配置面 | 位置 | 载体 | 热更新 |
|--------|------|------|--------|
| 环境变量 | 进程环境 | `EVERBLOOM_*`（55+ 个） | 否（需重启引擎） |
| 策略规则 | `EVERBLOOM_POLICY_RULES` | JSON 或 `.hpol` | 是（`SET_PROTECTION_MODES` 等） |
| 白名单 | `EVERBLOOM_ALLOWLIST_FILE` | JSON | 是 |
| BYOVD 清单 | `data/vulnerable_drivers.json` | JSON | 是（`RELOAD_VULNERABLE_DRIVERS`） |
| YARA 规则 | `EVERBLOOM_RULES_DIR` | `.yar` | 是 |
| 哈希库 | `EVERBLOOM_HASH_DB` / `EVERBLOOM_LEGACY_HASH_DB` | SQLite | 是（`RELOAD_HASH_DATABASE`） |
| 威胁情报 | `EVERBLOOM_THREAT_INTEL_DB` | SQLite | 是 |
| AI 模型 | `EVERBLOOM_AI_MODEL` + 边车 | ONNX + JSON | 是（`IMPORT_MODEL`） |
| UI 偏好 | `%LOCALAPPDATA%` | JSON | 是（GUI 重建） |
| 驱动 altitude | 服务注册表键 | `REG_SZ` | 是（需重启服务） |

## 10.2 策略规则（`EVERBLOOM_POLICY_RULES`）

### 两种格式

**JSON 格式**（`data/policy_rules.json` / `policy_rules.example.json`）：

```json
{
  "version": 1,
  "rules": [
    { "id": "sample-blocked-process", "kind": "process",
      "target": "C:\\Temp\\EverbloomSecurity\\blocked-sample.exe",
      "action": "block", "enabled": false },

    { "id": "documentation-network-example", "kind": "network",
      "address": "192.0.2.1", "port": 443,
      "action": "block", "enabled": false },

    { "id": "protected-registry-example", "kind": "registry",
      "target": "\\REGISTRY\\MACHINE\\SOFTWARE\\EverbloomSecurity",
      "action": "block", "enabled": false },

    { "id": "protected-mbr-example", "kind": "raw_disk",
      "target": "\\Device\\Harddisk0\\DR0",
      "action": "block", "enabled": false }
  ]
}
```

**`.hpol` 格式**（`data/policy_rules.hpol`）—— 更易手写：

```
# Everbloom Policy Language smoke-test profile.
# English and 简体中文 keywords are accepted.
version 1

block process "C:\ProgramData\EverbloomSecurity\quarantine\blocked-sample.exe" id "quarantine-process"
阻断 文件 "C:\ProgramData\EverbloomSecurity\quarantine\blocked-sample.exe" 规则名 "隔离文件"
禁止 网络 "192.0.2.1" 端口 443 规则名 "文档网络测试"
```

### 双语关键字

JSON 与 `.hpol` **都**接受英文与简体中文别名：

| 英文 | 简体中文 |
|------|----------|
| `process` | `进程` |
| `file` | `文件` |
| `network` | `网络` |
| `block` | `阻断` / `拦截` / `禁止` |

### 五种规则类型

| kind | 匹配语义 |
|------|----------|
| `process` | **精确**映像路径匹配 |
| `file` | **精确**文件路径匹配（create / write / set-information 强制点） |
| `network` | IPv4 地址匹配，可选目的端口（省略 `port` 则封禁该地址的所有端口） |
| `registry` | 注册表键路径匹配 |
| `raw_disk` | 裸磁盘设备路径匹配 |

### 约束

| 约束 | 值 / 说明 |
|------|-----------|
| 每种类型的规则上限 | **64 条** |
| 动作 | 仅 `block` |
| 通配符 | **不支持** |
| 存储位置 | 驱动保留在**非分页内存** |
| 强制点 | process / minifilter / WFP 三个拦截面 |
| 驱动缺失 | 报告为 `unsupported`，**不**让扫描器失败 |
| 校验时机 | **任何规则下发到驱动之前** |

### 生产部署建议（来自 `docs/config/protection_rules.md`）

> *For production, copy `data/policy_rules.example.json` to a deployment-owned, ACL-protected path and set only the rules that are intentionally managed.*

即：

- 示例文件**默认全部 `enabled: false`**，是刻意的安全默认；
- 生产环境应复制到**部署方拥有的、受 ACL 保护的路径**；
- 仓库自带的 `data/policy_rules.json` 是**冒烟测试档案**——只封禁一个精确的隔离样本路径与文档保留地址 `192.0.2.1:443`，**不**封禁任何正常 Windows 可执行文件或真实威胁情报地址；
- 真实威胁指标应通过**签名/本地威胁情报库工作流**导入，而不是硬编码进源文件。

### 为什么"精确匹配、无通配符"

驱动侧的路径匹配是在内核里手工实现的（`normalize_path` / `split_components` / `dos_path_suffix_matches`，见 [第 6.11 节](06-内核驱动.md#611-内核策略引擎kernel_policycpp938-行)）。通配符匹配在内核里代价高且容易写出病态回溯。精确匹配 + 64 条上限的组合，使内核侧的匹配成本**严格有界**且可预测。

## 10.3 白名单（`EVERBLOOM_ALLOWLIST_FILE`）

```json
{
  "enabled": true,
  "allow_builtin_system_processes": true,
  "paths": [],
  "sha256": []
}
```

| 字段 | 含义 |
|------|------|
| `enabled` | 总开关 |
| `allow_builtin_system_processes` | 自动放行内建系统进程 |
| `paths` | 路径白名单 |
| `sha256` | 哈希白名单 |

### 语义（关键）

白名单**只压制静态/AI 层的噪声判定**，不压制权威来源：

| 来源 | 是否被白名单压制 |
|------|------------------|
| 启发式 / AI | ✅ 压制 |
| 精确哈希命中 | ❌ 不压制 |
| YARA 命中 | ❌ 不压制 |
| 沙箱观察到的动态行为 | ❌ 不压制 |

这条规则防止"加了白名单 = 免检"（见 [第 4.2 节](04-扫描引擎.md#42-扫描流水线scannerrs2851-行)）。

## 10.4 BYOVD 清单（`data/vulnerable_drivers.json`）

```json
{
  "drivers": [
    "BdApiUtil64.sys",
    "zam64.sys",
    "BootRepair.sys",
    "EnPortv.sys",
    "wsftprm.sys",
    "TrueSightKiller.sys",
    "llama.sys",
    "ollama.sys"
  ]
}
```

**BYOVD**（Bring Your Own Vulnerable Driver）是攻击者利用合法签名但有漏洞的驱动来绕过驱动签名强制的手法。

### 关键设计：**basename 精确清单**

扫描流水线的第 3 步用这个清单做早期判定。源码注释明确要求：

> *"Keep this basename list exact; do not treat arbitrary `.sys` files as malicious merely because they are kernel modules."*

即：**不能因为文件是 `.sys` 就当恶意**。清单是精确的 basename 列表，不是扩展名规则。

### 两侧实现

同一个清单在内核与用户态各有一份实现：

| 位置 | 函数 |
|------|------|
| 用户态 | `driver_bridge.rs::known_vulnerable_driver_name()` |
| 内核 | `kernel_policy.cpp::is_known_vulnerable_driver_basename()` |

热更新命令：`RELOAD_VULNERABLE_DRIVERS`（从默认位置重新加载）。

## 10.5 模型契约（`model_contract.json`）

```json
{
  "output": {
    "output_index": 1,
    "malicious_index": 1,
    "kind": "probability"
  }
}
```

| 字段 | 含义 |
|------|------|
| `output_index` | 模型第几个输出张量是裁决输出 |
| `malicious_index` | 该张量里第几个分量表示恶意 |
| `kind` | 输出语义（`probability` = 概率值） |

这个 102 字节的文件是**引擎与训练侧的解码契约**。模型可以换（`IMPORT_MODEL`），只要边车契约说明清楚"哪个输出是恶意概率"。

## 10.6 特征顺序（`features.json`）

22,894 字节，**1,283 个元素**的特征顺序定义。

用途：告诉引擎"输入张量的第 i 维对应哪个特征"。这使模型与特征抽取器可以独立演进，只要 `features.json` 记录了正确的映射。

> **注意**：1,283 维是**离线/EMBER 对齐**布局（见 [第 5.5 节](05-检测层详解.md#55-另一套特征布局enginesrcfeatures)），与运行时 12 维契约是两套东西。

## 10.7 驱动 altitude（服务注册表键）

```
HKLM\SYSTEM\CurrentControlSet\Services\<服务名>\Instances\<实例名>\Altitude
```

| 项 | 值 |
|----|-----|
| 类型 | **`REG_SZ`**（字符串） |
| minifilter 值 | `329671` |
| 对象句柄值 | `329670` |

> ⚠️ 紧邻的 `ProtectedPaths` 是 `REG_MULTI_SZ`，很容易顺手写成 MULTI_SZ——Filter Manager 会因此**拒绝该实例**。

**altitude 不编译进驱动**：Filter Manager 在加载时从注册表读取。因此改注册表 + 重启服务即可调整，无需重新编译。

详见 [第 6.8–6.9 节](06-内核驱动.md#68-minifilter-altitude-策略)。

## 10.8 驱动 INF（`driver/package/everbloom_driver.inf`）

```ini
Class          = AntiVirus
ClassGuid      = {b1d1a169-c54f-4379-81db-bee7d88d7454}
CatalogFile    = everbloom_driver.cat
DriverVer      = 08/04/2026,1.0.0.0
LoadOrderGroup = "FSFilter Anti-Virus"
Dependencies   = FltMgr

[SourceDisksFiles]
everbloom_driver.sys

[Strings]
ServiceName     = "EverbloomSecurity"
DefaultInstance = "EverbloomSecurity Instance"
Altitude        = "329671"
```

### 命名约定（重要）

| 用途 | 形式 | 示例 |
|------|------|------|
| **人读的显示名** | 带空格 | `ServiceDisplayName = "Everbloom Security"`、`installer.iss` 的 `AppName` |
| **标识符 / 路径 / 文件名 / 服务名 / 设备名** | **无空格** | `\Device\EverbloomSecurity`、`everbloom_driver.sys`、`ServiceName = "EverbloomSecurity"` |

这条区分踩过坑：文档改名时若把 `HeliosAV` 一律换成带空格的 `Everbloom Security`，会把 `\\.\HeliosAV` 变成 `\\.\Everbloom Security`，与实际设备名不符。

### `[InstanceAddReg]`

写入三个注册表项：`Instances`、`Altitude`、`Flags`。

### 目录文件（`.cat`）

`CatalogFile = everbloom_driver.cat` 声明的编目文件必须覆盖 INF 与 SYS。生成工具：

```
C:/Program Files (x86)/Windows Kits/10/bin/10.0.28000.0/x86/Inf2Cat.exe
MSYS2_ARG_CONV_EXCL='*' Inf2Cat /driver:"<绝对路径>" /os:10_X64
```

## 10.9 YARA 规则（`EVERBLOOM_RULES_DIR`）

```
data/rules/
├── everbloom_core.yar       933 行
└── everbloom_extended.yar  1221 行
```

共 **2,154 行**规则。安装到 `bin/data/rules/`。

### 完整性校验

`yara.rs::verify_rule_integrity(manifest_path, source_hashes)` 配合 `EVERBLOOM_RULE_INTEGRITY_MANIFEST` 校验规则文件哈希——防止"规则被替换成空规则集"的静默失效。

### 版本

`YaraScanner::version()` 参与缓存键（`ScanContext.yara_version`）。规则更新后旧缓存自动失效。

## 10.10 哈希库（SQLite）

| 文件 | 用途 |
|------|------|
| `hashdb/HashDB.db`（23.8 MB） | 历史哈希库，随包分发 |
| `data/local_hashes.sqlite` | 本地增量哈希库 |

### `hashes` 表

支持五种摘要列：

| 列 | 说明 |
|----|------|
| `md5` | MD5 |
| `sha1` | SHA-1 |
| `sha256` | SHA-256 |
| `ssdeep` | 标准 ssdeep 模糊哈希 |
| `ssdeep-lite` | 简化模糊哈希（历史格式，仍可读取） |

### 模糊匹配规则

| 常量 | 值 |
|------|-----|
| 最小块大小 | 3 |
| 主/次哈希长度上限 | 64 / 64 |
| 匹配阈值 | **85**（相似度百分比） |
| 滚动窗口 | 7 字节 |

**只有恶意记录能产生恶意裁决**：模糊匹配只在对方是已知恶意时才产生结论（见 [第 5.1 节](05-检测层详解.md#51-哈希层hashrs)）。

## 10.11 威胁情报（SQLite）

| 文件 | 用途 |
|------|------|
| `data/indicators.db` | IoC 指标库 |
| `data/public_threat_intel.sqlite` | 公共威胁情报 |

### 数据模型

| 表 | 内容 |
|----|------|
| `hashes` | 样本哈希 |
| `iocs` | 网络指标 |

**每条网络指标必须携带**：来源、置信度、时间戳、引用、可选过期时间。

### 加载门限

```rust
const DEFAULT_MIN_CONFIDENCE: u8 = 70;
```

只有 `confidence >= 70` 且**未过期**的 IoC 才被加载。

### 数据源

| 源 | 内容 | 认证 |
|----|------|------|
| MalwareBazaar | 恶意样本哈希 | 无 |
| URLhaus | 恶意 URL | **仅在线查询** |
| ThreatFox | IoC | `THREATFOX_AUTH_KEY` |

## 10.12 配置 schema（`docs/config/`）

```
docs/config/
├── config_example.json
├── root_config_schema.json
├── engine_config_schema.json
├── pipeline_config_schema.json
├── ai_assistant_config_schema.json
├── deep_ai_config_schema.json
├── behavior_config_schema.json
├── cache_config_schema.json
├── rule_engine_config_schema.json
└── protection_rules.md
```

### 示例配置结构（`config_example.json`）

```json
{
  "cache": {
    "whitelist": { "backend": "memory" },
    "hash": { "backend": "lmdb", "path": "cache/hash.db", "map_size": 10737418240 }
  },
  "engine": {
    "auto_quarantine": true,
    "whitelist": ["C:\\\\Windows\\\\System32\\\\*.exe"],
    "thresholds": { "entropy_high": 7.5, "overlay_ratio": 0.15 }
  },
  "pipeline": {
    "enabled_stages": ["cache", "rule", "ai", "behavior"],
    "rule_engine": { "rules_path": "yara_rules/" },
    "ai_assistant": { "model_path": "models/assistant.pkl", "enabled": true },
    "deep_ai": { "model_path": "models/deep.pth", "image_size": 128, "enabled": true },
    "behavior_analyzer": {
      "keywords": ["CreateRemoteThread", "VirtualAlloc"],
      "enabled": true
    },
    "weights": { "hash": 100, "rule": 50, "ai": 20, "deep_ai": 30, "behavior": 60 }
  }
}
```

### 阶段与权重

`pipeline.enabled_stages` 是可裁剪的检测阶段列表（`cache` / `rule` / `ai` / `behavior`）。`weights` 给出各阶段的相对权重——注意 `hash: 100` 最高，反映"精确哈希命中是权威证据"这一原则。

### 阈值

`engine.thresholds`：

| 参数 | 示例值 | 对应实现 |
|------|--------|----------|
| `entropy_high` | 7.5 | 启发式的 `HIGH_ENTROPY_WINDOW_THRESHOLD`（源码中为 7.40） |
| `overlay_ratio` | 0.15 | 覆盖层比例（加壳指示） |

### schema 文件的作用

每个 `*_config_schema.json` 定义对应配置段的合法字段与取值范围。Python 侧的 `python/everbloom_config/schema.py` 与 `factory.py` 消费这些 schema，使"配置文件写错"在**加载阶段**就被发现。

## 10.13 UI 偏好持久化

由 `WinUIApp.cpp` 的 `PersistUiPreferences()` / `LoadUiPreferences()` 管理，存储在用户配置目录。

持久化内容对应 `UiFeatureSettings`（见 [第 7.2 节](07-桌面GUI.md#72-应用主体winuiappcpp--winuiapph)）：

```cpp
bool yara_enabled{true};
bool heuristic_enabled{true};
bool ai_enabled{false};
bool sandbox_enabled{false};
bool cloud_placeholder_enabled{false};
bool r3_enabled{false};
bool driver_enabled{false};
bool notifications_enabled{true};
bool translucent_panels{true};
uint8_t transparency_percent{12};       // UI 钳制在 0..55%
bool start_with_windows_enabled{false};
```

以及 `UiStyle`（7 种）、`UiLanguage`（5 种）、`UiAccent`（4 种）与背景图路径。
