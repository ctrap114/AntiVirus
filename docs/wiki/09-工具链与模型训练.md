## 9.2 构建与打包工具

### `build_modules.ps1`（275 行）

**逐模块构建**，每个模块的产物落在 `artifacts/<module>/`。设计要点：

- **失败隔离**：一个模块构建失败不影响其它模块——每个模块的结果记录在 manifest 里；
- **Ninja 需要 `CMAKE_BUILD_TYPE`**：脚本会显式传入（Ninja 是单配置生成器，不像 MSBuild 有默认配置）。

### `build_install_full.ps1`（209 行）

完整的安装包生产链：

1. 可选调用 `driver/package/sign_driver.ps1` 签名驱动；
2. 暂存 `everbloom_driver.inf` + 第一个 `*.cat` + `everbloom_driver.sys` 到 `artifacts/package/install/driver`；
3. 从 `jrsoftware/issrc` 引导 3 个 Inno Setup 语言文件；
4. 调用 `build_installer.ps1`；
5. 写 `build-report.json`。

### `build_installer.ps1`（79 行）

调用 `ISCC.exe`（Inno Setup 6 编译器，默认 `D:\Inno Setup 6\ISCC.exe`）执行 `tools/installer.iss`。

### `bootstrap_dev.ps1`（61 行）

开发环境引导：检查工具链、准备 vcpkg、拉取依赖。

### `build_native.ps1`（15 行）

原生构建的薄封装。

## 9.4 特征与数据集工具

### `extract_features.py`（840 行）—— EMBER-2025 风格特征提取

文档字符串说明了核心策略：

> *提取时高维全面（~2671 维），存储时极致压缩（CSR 稀疏 + 特征哈希降维），坚决不存原始样本（只存特征向量 + 标签 + 元数据）。*

**特征维度构成**：

| 组 | 维度 | 内容 |
|----|------|------|
| `byte_histogram` | 256 | 文件前 1024 字节的字节直方图 |
| `pe_header` | 62 | PE 头关键字段 |
| `section_info` | 255 | 节区名 hash + 节区大小/熵值/属性 |
| `imports` | 1,280 | IAT 导入函数名 hash |
| `exports` | 128 | EAT 导出函数名 hash |
| `data_directories` | 100 | 数据目录条目 |

**"坚决不存原始样本"** 是一条重要的合规与安全设计：数据集只含特征向量、标签与元数据，不含可执行文件本身。这使数据集可以安全地存储、传输与共享。

**CSR 稀疏 + 特征哈希降维**：1,280 维的导入表在单个样本上绝大多数是 0，用 CSR（Compressed Sparse Row）稀疏存储能把体积降低一到两个数量级。

### `download_ember.py`（100 行）/ `extract_ember.py`（70 行）

EMBER 数据集的下载与解包。

### `import_real_dataset.py`（395 行）—— 保守的本地数据集导入

文档字符串强调：

> *The script is intentionally conservative: it never contacts the network and only ever reads from paths the operator passes in.*

**输出**：`labels.csv` + `manifest.json`，格式与 `train_ai_model.py` 的输入契约一致，因此手动导入的数据集可以**直接接入**训练流水线，无需额外胶水代码。

**支持的输入**：`--source <dir>` 下含 `malware/` 与 `benign/` 子目录（子目录名大小写不敏感）。

**"从不联网"** 是刻意的：这个脚本处理的是操作者手动授权的数据，不应该有任何隐式网络行为。

## 9.5 模型训练工具

### `train_feature_cnn.py`（306 行）—— 运行时 12 维模型

文档字符串明确契约：

> *This script produces an ONNX model that is compatible with the runtime loader in `engine/src/layers/ai.rs`. The engine expects a float32 tensor of shape `[1, 12]` containing the same feature layout defined by `AiModel::extract_features`.*

**输入形状 `[1, 12]`** 是硬契约——必须与引擎的 12 维特征布局逐位对应。

### `train_ai_model.py`（299 行）

通用 AI 模型训练入口，接受 `labels.csv` + `manifest.json`。

### `train_adversarial_model.py`（422 行）—— 对抗训练

文档字符串：

> *Train a robust EverbloomSecurity ONNX classifier with constrained PGD examples. This is a defensive feature-space trainer. It consumes numeric feature vectors and labels, never edits input files, and never emits executable samples.*

关键限定：

- **"defensive feature-space trainer"** —— 在**特征空间**做对抗训练，不操作真实文件；
- **"never edits input files, and never emits executable samples"** —— 不产出可执行样本，避免生成对抗恶意软件；
- **PGD（Projected Gradient Descent）** 是标准的对抗样本生成方法，此处用于**增强模型鲁棒性**而非攻击。

输入格式支持：NumPy 数组、JSONL 记录、以及项目的 `dense_test_features.npy` / `dense_test_labels.npy` 测试固件。

输出：单输入张量模型 + Rust 兼容的 `model_contract.json` 边车文件。

### EMBER 系列训练脚本

| 脚本 | 行数 | 说明 |
|------|------|------|
| `train_ember_2018.py` | 503 | EMBER 2018 数据集训练 |
| `train_ember_2025.py` | 236 | EMBER 2025 数据集训练 |
| `train_ember_2025_v1.py` | 333 | EMBER 2025 的 v1 版本（保留对比） |

EMBER 2018 是学术界广泛使用的 PE 恶意软件数据集，用它训练使模型的**基线可复现、可与其他研究对比**。

### `train_synthetic_experiment.py`（306 行）

合成语料实验。与引擎的 `--train-synthetic` 带外模式配合使用。

### `train_pyas_transformer.py`（18 行）

Transformer 架构的实验入口（薄封装）。

## 9.6 模型转换工具

三个转换脚本解决同一类问题：**训练框架产出的 ONNX 图，`tract-onnx` 不一定能直接执行**。

### `convert_feature_cnn_for_tract.py`（135 行）

文档字符串精确描述了问题与解法：

> *The original export uses a constant-index `GatherND` pattern for `adaptive_avg_pool1d(output_size=8)`. tract-onnx 0.23 cannot optimize that graph, while the same computation is representable as `AveragePool(kernel_shape=[81], strides=[80])` for the model's fixed post-convolution length of 641.*

即：

- **问题**：PyTorch 导出 `adaptive_avg_pool1d(output_size=8)` 时用的是常量索引 `GatherND` 模式，`tract-onnx 0.23` 无法优化这个图；
- **解法**：该模型卷积后长度固定为 641，因此 `adaptive_avg_pool1d(8)` 等价于 `AveragePool(kernel_shape=[81], strides=[80])`。

脚本还负责**嵌入外部权重**（把 `.onnx.data` 内联进 `.onnx`）并写出两个边车文件：

| 边车 | 内容 |
|------|------|
| `features.json` | 1283 元素的特征顺序 |
| `model_contract.json` | 把输出 #1 解码为恶意概率 |

### `convert_onnx_for_everbloom.py`（238 行）—— 通用归一化器

文档字符串强调其**窄契约**：

> *This converter deliberately has a narrow contract. It does not execute a model, rewrite arbitrary graphs, or claim that unsupported multi-input models are compatible. It validates the graph, optionally converts the default ONNX opset to the conservative target used by the bundled models, embeds external weights, and writes the sidecars consumed by the Rust scanner.*

关键常量：

```python
MAX_MODEL_BYTES = 512 * 1024 * 1024      # 512 MiB
DEFAULT_TARGET_OPSET = 12                # 保守的 opset 目标
```

**"不执行模型、不重写任意图、不声称不支持的多输入模型兼容"** —— 这三条"不做"是刻意的：转换器宁可明确失败，也不要产出一个"看起来转换成功但实际不可用"的模型。

### `convert_tree_ensemble_for_tract.py`（233 行）

稠密树集成模型的转换（对应 `EVERBLOOM_DENSE_TREE_MODEL`）。

## 9.7 质量基线工具（`run_quality_baseline.py`，342 行）

文档字符串：

> *Run repeatable YARA and optional ONNX quality baselines. The corpus is intentionally synthetic and inert. This tool measures regression signals, not production malware-detection efficacy.*

**门控模式**：

```bash
python tools/run_quality_baseline.py --gate --max-fp-rate 0.01 --max-fn-rate 0.05 --max-p95-ms 500
```

`--gate` 使脚本在任一阈值被违反时**返回非零退出码**，可以直接接入 CI 在检测或性能退化时让构建失败。

三个门控指标：

| 参数 | 含义 |
|------|------|
| `--max-fp-rate` | 最大误报率 |
| `--max-fn-rate` | 最大漏报率 |
| `--max-p95-ms` | 最大 P95 延迟（毫秒） |

**诚实的能力边界声明**：脚本明说它衡量的是**回归信号**，不是生产环境的恶意软件检测效能——因为语料是合成且惰性的。这条声明避免了"基线通过 = 产品有效"的误读。

## 9.8 威胁情报工具（`build_local_hashdb.py`，485 行）

文档字符串：

> *The updater stores hashes in `hashes` and network indicators in `iocs`. Network indicators always carry source, confidence, timestamps, a reference, and an optional expiry so the scanner never treats a stale feed item as a permanent block rule.*

### 使用示例

```bash
# 哈希 + URL（URLhaus 仅在线查询）
python tools/build_local_hashdb.py --out data/local_hashes.sqlite \
    --malwarebazaar --mb-limit 500 --urlhaus-recent --urlhaus-limit 500

# ThreatFox IoC（需要 API key）
python tools/build_local_hashdb.py --out data/local_hashes.sqlite \
    --threatfox --threatfox-api-key "$env:THREATFOX_AUTH_KEY"
```

### 数据模型

| 表 | 内容 |
|----|------|
| `hashes` | 样本哈希（md5 / sha1 / sha256 / ssdeep / ssdeep-lite） |
| `iocs` | 网络指标（域名 / IP / URL） |

网络指标**始终**带：来源、置信度、时间戳、引用、可选过期时间。这是"绝不把过期情报当永久封禁规则"的实现保证。

## 9.13 训练流水线全貌

把上述工具串起来，完整的模型迭代流程是：

```
① 数据获取
   ├─ tools/download_ember.py + tools/extract_ember.py     （公开数据集）
   ├─ tools/import_real_dataset.py                          （本地授权数据集）
   └─ tools/build_local_hashdb.py                           （威胁情报）

② 特征抽取
   └─ tools/extract_features.py  →  CSR 稀疏特征 + labels.csv + manifest.json

③ 训练
   ├─ tools/train_ai_model.py          （通用）
   ├─ tools/train_feature_cnn.py       （12 维运行时模型）
   ├─ tools/train_ember_2018/2025*.py  （公开数据集基线）
   ├─ tools/train_adversarial_model.py （PGD 对抗训练）
   └─ tools/train_synthetic_experiment.py（合成语料实验）

④ 转换（适配 tract-onnx）
   ├─ tools/convert_feature_cnn_for_tract.py
   ├─ tools/convert_tree_ensemble_for_tract.py
   └─ tools/convert_onnx_for_everbloom.py   （通用归一化）

⑤ 校验
   └─ tools/run_quality_baseline.py --gate  （误报率 / 漏报率 / P95 延迟门控）

⑥ 部署
   ├─ 引擎侧：替换 everbloom_feature_cnn.onnx / features.json / model_contract.json
   └─ 内核侧：tools/ 导出器生成 EVERBLOOM_MATRIX_MODEL 的 C 权重表
```

### 两套模型的部署差异

| | 引擎模型 | 内核模型 |
|---|---|---|
| 文件 | `.onnx` + 两个边车 | C 权重表（`kernel_model.cpp`） |
| 部署 | 换文件（`IMPORT_MODEL` 命令可热更新） | 换表 + 重编译（换表不改代码） |
| 输入 | PE 结构 12 维（浮点） | 路径/命令行 12 维（整数，`[0,127]`） |
| 推理 | `tract-onnx` | 纯整数 Q31 定点核心 |

内核模型当前是**未训练的引导值**，设计上预留了"换表不改代码"的替换路径——`kernel_model.cpp` 里的权重表是唯一需要替换的部分。

## 9.14 能力考量

| 考量 | 设计 |
|------|------|
| 数据集合规 | 不存原始样本，只存特征向量 + 标签 + 元数据 |
| 导入脚本安全 | 从不联网，只读操作者指定的路径 |
| 对抗训练边界 | 只做特征空间防御训练，不产出可执行样本 |
| 转换器诚实 | 明确"不做"清单，宁可失败也不产出不可用的模型 |
| 基线声明诚实 | 明说衡量的是回归信号而非生产效能 |
| CI 可接入 | `--gate` 非零退出码 |
| 情报时效 | IoC 强制带过期时间 |
| 模型可换 | 引擎换文件；内核换表不改代码 |
